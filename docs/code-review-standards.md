# cdt-worker 代码审查标准与流程

> 本文件是 `cdt-worker`（Cloudflare Worker 版 CDT-Monitor）的**唯一审查口径**。
> 所有 PR 合入前必须对照本文执行。与本文冲突的历史约定以本文为准。
> 首次制定：2026-09-27 · 维护者：项目 owner + 审查人

## 0. 项目硬约束（决定审查重点）

这不是普通 Web 应用，它跑在 **Cloudflare 免费额度**上。任何"功能上都对、但会多花额度"的写法，
在本项目里等同于**功能性缺陷**。审查时额度优先级高于代码优雅度。

| 维度 | Free 计划限额 | 本项目占用的估算 | 生死线 |
|---|---|---|---|
| **CPU time** | **10 ms / 次调用**（HTTP 与 Cron 各算一次） | 一轮监控 5 账号 ≈ 6–9 ms | 🔴 崩溃线 |
| **Subrequests** | **50 / 请求** | 一轮监控 ≈ 53–68 | 🔴 崩溃线 |
| Workers 请求数 | 100,000 / 天 | 每 5 分钟 1 cron + 前端轮询 | 🟡 |
| **D1 写入** | 100,000 行 / 天 | 5 账号 ≈ 6,000–9,000 行/天 | 🟢 余量充足 |
| D1 读取 | 5,000,000 行 / 天 | 日志页翻页是主要风险点 | 🟡 |
| D1 存储 | 5 GB | traffic_stats 30 天 ≈ 4 万行 | 🟢 |
| 出站并发连接 | 6 / 请求 | 账号并行上限必须 ≤ 6 | 🔴 |
| Cron Triggers | **5 个 / 账号**（账号级） | 占用 1 个 | 🟡 |
| Worker 体积 | 1 MB（Free）/ 3–10 MB | 单文件 SPA 已接近 | 🟡 |
| Memory | 128 MB / isolate | 模块级缓存若干 Map | 🟡 |
| Secret 可读性 | **只写不可读** | 故有 CRON_SECRET 托管机制 | 设计约束 |

**核心判断原则**：一句话 —— *一次监控周期的成本 ÷ 账号数*，必须显著低于上面每一行。
新增任何"每轮都做"的操作前，先算它一年会多花多少次调用。

## 1. 严重度分级

| 级别 | 标识 | 定义 | 处理要求 |
|---|---|---|---|
| **阻断** | 🔴 P0 | 会导致**额度耗尽/1101/CPU 超限**、**数据丢失**、**未授权访问**、或**远程触发破坏性操作** | 必须合入前修复。不接受"下个版本再补" |
| **高** | 🟠 P1 | 功能在特定路径下失效、可被外部放大、或造成可观测的成本浪费 | 本迭代内修复，或显式拆 ticket + 加 TODO 注释 |
| **中** | 🟡 P2 | 代码质量、可维护性、潜在隐患 | 记 ticket，排期修 |
| **低** | 💭 P3 | 命名、死代码、注释缺失 | 顺带清理，不单独阻塞 |

## 2. 六大审查维度

### 维度 A — 正确性
- [ ] 边界值：0、负数、空串、极大值、`parseInt` 的 `NaN`/`1e9` 陷阱
- [ ] `parseInt(x) || default` 的**假值回退陷阱**（`0 || 90 === 90`，`-1 || 90 === -1`）
- [ ] 时区：`datetime('now')` 是 **UTC**，ISO 字符串需要 `+ 'Z'`，东八区偏移 8 小时的经典坑
- [ ] 并发：读-判断-写 三步操作是否存在竞态；幂等键是否真的覆盖所有重复路径
- [ ] 跨午夜窗口（定时开/关机）的日期归属是否一致
- [ ] 状态机：Starting/Stopping/Pending/Unknown 的过渡态不被误判为稳定态
- [ ] 时间：**一律用配置时区的墙钟**，别用 `toISOString().slice()`

### 维度 B — 安全
- [ ] **鉴权**：每个路由是否显式声明 `scope`？无 scope 的接口是否真无需鉴权？
- [ ] **CSRF**：`admin` 会话 + 非安全方法必须走双提交；API Key 走 header 天然免疫，不要误伤
- [ ] **密钥泄露面**：任何出现在 URL 查询参数、日志、错误信息里的机密
- [ ] **密钥存储强度是否一致**：AK/SK 用 AES-GCM，通知通道凭据呢？
- [ ] **时序攻击**：比较密钥/令牌必须用常量时间，且先做长度归一化
- [ ] **限流**：任何会调用外部 API 或产生副作用的接口都要限流（含"测试"类按钮）
- [ ] **入参范围校验**：写在后端，不能依赖前端 `min/max`
- [ ] **XSS**：前端所有 `innerHTML` 拼接处必须走 `esc()`；`escHtml()` 不转义单引号，只适合文本节点
- [ ] **响应头**：安全头统一在出口加，不要每个分支各写一遍

### 维度 C — 免费额度与性能（本项目最高优先级）
- [ ] **子请求预算**：一次调用内 D1 读 + D1 写 + `fetch` 之和 ≤ **40**（留 10 的余量给 50 上限）
- [ ] **CPU 预算**：新增的每轮执行路径上，CPU 增量 < 0.5 ms
- [ ] 能用 `DB.batch()` 合并的写操作，**不要逐个 `run()`** —— batch 只算 1 个 subrequest
- [ ] 被防抖跳过的路径**必须提前返回**，不能先做完重活再跳过
- [ ] 只在真正需要时读全量配置（`getConfig` 会解密所有账号 AK/SK）
- [ ] isolate 内的缓存（模块级 `Map`）是否设置了清理/上限？
- [ ] 新增的"只增不删"的表或日志，是否有对应的清理路径？

### 维度 D — 可维护性
- [ ] 默认值是否只有一处定义？数据源冲突是历史上出过真 bug 的地方
- [ ] 注释是否解释了**为什么**，而不是复述**做了什么**？
- [ ] 是否有死代码（未使用的导出、永不写入的列、无用参数）？
- [ ] 错误处理：是否 catch 了真正预期的失败，而不是 `catch {}` 吞掉一切？

### 维度 E — 测试
- [ ] 新增的**纯函数**必须有单测（本项目大部分逻辑都在 `time.ts` / `triggers.ts` 这类纯函数里，天生可测）
- [ ] 单测断言要锁住**语义**而非实现细节；断言写反是本项目出现过的真实事故
- [ ] `tsc --noEmit` 为 0 错误，`npm test` 全绿 —— 这是合入的硬门槛
- [ ] 如果一个 bug 修起来很痛，说明当初把它写成纯函数的选择是错的

### 维度 F — 可观测性
- [ ] 用户能否从日志判断"这轮到底跑了没有、是谁叫起来的"？
- [ ] 失败路径是否有可诊断的日志（而不是一句"操作失败"）？
- [ ] 是否会刷屏？限流要写进 key 里（如 `trigger_gap:source:hour`）

## 4. 审查流程

### 阶段 1：提交前（作者自审）
1. 打开本文的维度 Checklist，逐条过一遍改动涉及的部分
2. 如果改动触碰监控主循环（`runMonitorCycle` / `processAccount` / `store.ts` 的 D1 调用），
   **手算一遍子请求增量**，写进 commit message
3. 跑门槛命令（上文 3 节）

### 阶段 2：PR / 提交时（机器）
`git commit` 后按既有约定推送，GitHub 侧 CI 跑 tsc + vitest。

### 阶段 3：人审（审查人）
1. **先看 diff 的整体意图**，再看细节。不要一上来逐行
2. 重点扫：鉴权分支、SQL、循环内的 I/O、模块级状态
3. 给出分级意见（🔴🟠🟡💭），每条必须带：文件:行号 → 为什么 → 建议改法
4. **先肯定再批评**：好的设计要指出来（例如 `shouldNativeRun` 把节流做成纯函数、`tryAcquireMonitorSlot`
   用条件 UPSERT 做原子抢占，这两处都是本项目值得保持的范式）
5. 48 小时内 response；P0 不过不复

### 阶段 4：发布后
- 观察 CF Dashboard → Workers → Metrics：`CPU time` 与 `Exceeded CPU Time Limits`
- 观察 D1 → Metrics：`Rows read / Rows written`，确认没有贴近日上限
- 如果看到 1101（subrequest 超限）或 1102（CPU 超限），立刻回滚，**不要边修边跑**

### 备注：审查节奏约定
本项目是 owner 单人主导的持续加固循环（"报告 → 方案 → 改 → 验 → 推"）。
审查意见建议在**方案阶段**一次性给全，避免方案反复横跳。

## 5. 本项目已确认的反模式（看到就得警觉）

| 反模式 | 历史事故 | 正确写法 |
|---|---|---|
| `parseInt(x) \|\| default` | 传 `-1` 会被忠实采用，传 `0` 却悄悄变 90 | 显式范围校验后再 `?? default` |
| 先做重工再判断是否要跳过 | 每个被防抖跳过的轮次仍付全量 D1 开销 | 轻量判断放最前，命中直接 return |
| 多步"读→判→写"防抖 | 并发触发重复跑整轮监控 | 条件 UPSERT 单语句原子抢占 |
| 每个 D1 写各自 `run()` | subrequest 爆表 | `env.DB.batch([...])`，1 个 subrequest |
| 忽略 `datetime('now')` 是 UTC | 账单 TTL 偏移 8 小时 | 补 `'Z'` 或按 UTC 解析 |
| 定时补偿只做了一半 | 开机方向漏了补偿，实例整天不启动 | 对称地补（`/windowOver` 就是为此抽出来的） |
| 失败响应用 JSON | 用户看到 `{error:code:unauthorized}: command not found` | shell 场景返回首行 `#` 的纯文本 |
| 前端做了校验就当后端安全 | `min/max` 绕不过 curl | 后端白名单 + 范围校验 |
