# DDNS 轮换解析

> 场景：你有 2~5 台云服务器，在云厂商控制台设置了**错峰开关机**；
> 本功能负责**自动把域名解析切到当前该值班（在线）的那台机器**。
>
> 机器的开关机不由本系统控制 —— 你只需登记机器 IP 与排班，解析切换全自动。

功能已集成进 cdt-worker（代码级融合），与管理台共用同一套 D1、鉴权与日志，
无需额外部署一个 Worker。

---

## 一、核心概念

| 概念 | 说明 |
| --- | --- |
| **机器 machine** | 一台云服务器，主要字段是「名称 + 公网 IP」。开关机由你在云厂商控制台设置 |
| **分组 group** | 一个分组 = **一组机器 + 一个或多个域名记录**。例如「香港组」= 机器 1/2/3 → 域名 `a.example.com` |
| **DNS 凭据 credential** | 某家 DNS 厂商的 API 密钥，**独立配置、可被多条解析记录复用**（AES-GCM 加密存储） |
| **解析记录 record** | 分组下的一条 DNS 记录（厂商 + 域名 + 主机记录 + **引用凭据** + TTL） |

**一个分组可以同时挂多个域名（甚至跨厂商）**，它们永远被同步指向同一台当前值班机器的 IP。

> 凭据与记录分离：例如「阿里云主账号」配一次，就能被多条记录引用；换密钥只需改一处。
> 管理台**密码类字段**以密文存储，界面只回脱敏值（如 `abc****xyz`），留空即视为不修改。

### 前端结构（页内子标签）

DDNS 标签页内含 5 个子页，信息架构与参考项目 `ddns-rotation` 对齐：

| 子页 | 作用 |
| --- | --- |
| **概览** | 每个分组一张卡片：模式 / 时区 / 成员 / 域名 / 当前指向 / 兜底 IP，附快捷操作 |
| **机器** | 机器池（名称 + 公网 IP + 备注 + 启停） |
| **分组排班** | 分组清单 + 「排班」弹窗（参数与列随模式变化，机器用下拉勾选批量加入） |
| **解析记录** | 全部记录一览（分组 / 域名 / 厂商 / 凭据 / TTL / 当前值），支持单条下发 |
| **DNS 凭据** | 凭据增删改 + **连通测试** |

## 二、四种排班模式

### 1. `window` —— 按一天内时间段轮换

给每台机器填在线时段（与云厂商设置的开机时间保持一致），
系统按**分组时区**判断当前时间落在谁的时段内，就把域名解析给它。**支持跨天**。

```
机器 A  08:00 - 14:00
机器 B  14:00 - 20:00
机器 C  20:00 - 08:00   ← 跨天，自动识别为 20:00~23:59 + 00:00~07:59
```

三台错峰，域名自动跟着走。时段边界为**起点闭区间、终点开区间**
（08:00 属于 A，14:00 已属于 B）。

### 2. `rotate` —— 按多少天轮换

组内机器按各自的**值班天数**轮流，可各不相同：

```
机器 A 值班 10 天 → 机器 B 值班 10 天 → 机器 C 值班 10 天 → 回到 A（30 天一循环）
```

- **切换时刻**（默认 `03:00`）：早于该时刻仍算「前一天」的值班机器。
  这是刻意的——若机器 08:00 才开机，凌晨 00:00 就把解析切过去会指向一台关机的机器。
- **轮换基准日**（默认 `1970-01-01`）：轮换周期从这天开始算，调整它可改变当前由谁值班。

> 想实现「按月轮换」？把每台机器的值班天数填 30 即可。

### 3. `interval` —— 基准时间 + 每 N 天

与 `rotate` 用同一套「每台机器各自值班 N 天」的轮转内核，区别是轮换原点是一个
**精确到分钟的基准时间**（`anchor_at`，如 `2026-09-20 03:00`），而不是「基准日 + 每日切换时刻」两段式。

```
基准时间 2026-09-20 03:00
机器 A 值班 5 天 → 机器 B 值班 5 天 → 机器 C 值班 5 天 → 回到 A（15 天一循环）
```

适合「从某个时刻起，每台机器各跑 N 天、两台或多台轮着来」的简单心智。
轮换起点在**新建分组**时默认填当前时刻，也可以在分组的「排班」弹窗里直接改。

### 4. `static` —— 固定首台

不轮换，始终解析到排序最靠前的可用机器。

### 排班弹窗会随模式变

「排班」弹窗不是一套固定表单，选了什么模式就只给你那个模式要填的东西：

| 模式 | 弹窗上方的参数 | 成员表格的列 |
| --- | --- | --- |
| `rotate` | 切换时刻、轮换基准日（都在这里直接改） | 值班天数 / 排序 |
| `interval` | 轮换起点（精确到分钟） | 值班天数 N / 排序 |
| `window` | 无（模式说明） | 在线开始 / 在线结束 / 排序 |
| `static` | 无（模式说明） | 排序 |

- **加机器**用「添加机器到本组」的**下拉勾选**，可以一次勾多台再点「保存排班」一起加入；
  时段模式给新成员默认 `00:00–23:59`，避免刚加进来因没配时段而永不命中。
- **跨天时段**：结束时刻早于开始时刻即视为跨天，例如 `22:00 → 06:00` 命中 22:00–23:59 与 00:00–05:59，
  这一行会打上「跨天」标记；时段格式不对或留空会被拦下，提示你填写或勾「移除」。

### 兜底

所有机器都不在线（或都被停用）时，解析到分组的**兜底 IP**；
兜底 IP 留空则**保持上一次的解析不变**（不会把解析写坏）。

## 三、支持的 DNS 厂商

| 厂商 | provider id | 所需凭据 | 最小 TTL |
| --- | --- | --- | --- |
| Cloudflare | `cloudflare` | API Token（Zone → DNS → Edit 权限） | 60 |
| 阿里云云解析 | `aliyun` | AccessKey ID、AccessKey Secret | 600（免费版） |
| 腾讯云 DNSPod | `dnspod` | SecretId、SecretKey | 60 |
| name.com | `namecom` | 用户名、API Token | 300 |
| Spaceship | `spaceship` | API Key、API Secret | 60 |
| GoDaddy | `godaddy` | API Key、API Secret | 600 |

凭据在 D1 中**以 AES-GCM 加密存储**，管理台只回脱敏值（如 `abc****xyz`），
密文与明文都不会返回前端。

各厂商的注意事项：

- **Cloudflare**：开启橙云代理时 TTL 会被强制为 auto，切换几乎立即生效。
- **阿里云**：免费版最小 TTL 600 秒，低于该值会被自动上调。
- **Spaceship**：该厂商没有单条记录的修改接口，更新必须**整组提交**。
  本系统会先读取域名下全部记录、在内存中替换目标 A 记录、再整体写回，
  **不会删除你的 MX / TXT / CNAME 等其他记录**。
- **DNSPod**：需先在厂商控制台存在对应的 A 记录（本系统负责改，不负责建）。

## 四、使用步骤

1. 管理台 → **DDNS** 标签页
2. **DNS 凭据**：先配凭据（名称 + 厂商 + 密钥），可点「连通测试」验证密钥是否可用
3. **机器**：登记所有参与轮换的机器（名称 + 公网 IP）
4. **分组排班**：新建分组，选择排班模式（按天轮换 / 基准时间+每N天 / 按在线时段 / 固定首台）、时区、参数与兜底 IP
   - 日期与时间既能**直接输入**（`2026-09-28 03:00`），也能用下方的「年 / 月 / 日 / 时 / 分」**下拉点选**；
     新增分组时「轮换基准日」默认当天、「轮换起点」默认当前时刻。
   - 下方参数会随所选模式变化，只显示这个模式用得上的字段。
5. **排班**：点分组的「排班」按钮，用「添加机器到本组」的**下拉勾选**批量加机器，
   按模式填「值班天数 N」或「在线时段」（支持跨天），可调排序；上方参数可直接改（rotate 的切换时刻/基准日、interval 的轮换起点）
6. **解析记录**：点「新增记录」挂上域名（可多条、可跨厂商），选择厂商并**引用已有凭据**
7. 回到分组点**同步**（或顶部**立即同步**）验证

建议先点分组的**7 天预览**确认轮转顺序符合预期，再开启真实同步。

## 五、同步机制与额度

- **触发方式**：搭监控周期的便车执行（每轮监控末尾跑一次），
  **不额外占用 Cloudflare Cron 槽位与触发次数**。
- **幂等**：只有「目标 IP 与厂商当前值不一致」时才调用厂商写接口。
  按天轮换的分组**一天最多真正写一次**，几乎不消耗厂商 API 配额。
- **失败隔离**：DDNS 同步全程包 try/catch，出错只会写一条日志，
  绝不影响阿里云监控主流程。

## 六、日志

DNS 轮换相关日志写在**日志页 → DNS 轮换**分类（`type=ddns`）：

- 解析切换成功 → `ddns` 类型，记录「旧 IP → 新 IP」、命中的机器与原因
- 同步失败 → `error` 类型（归入「告警」分类），记录厂商返回的错误

同步汇总只在「有切换或有失败」时才写一条，避免每 5 分钟刷屏。

---

## 七、注意事项

1. **开关机时间要留缓冲**：建议在时段边界前后各留几分钟
   （如开机 08:00，时段填 `08:05-13:55`），避免解析切过去了机器还没起来。
2. **TTL 决定生效速度**：TTL 600 意味着最长 10 分钟才生效，建议设 60~300。
3. **时区按分组配置判定**（默认 `Asia/Shanghai`），不要用 UTC 思维推算——
   否则东八区会在时间差上错位一整天。
4. **凭据安全**：请为管理台设置强密码；DNS 凭据加密存储，但拥有管理员权限即可查看脱敏值。

## 八、接口一览（管理台内部使用）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/ddns/overview` | 全量概览（机器 + 分组含成员/记录 + 凭据脱敏值 + 厂商元信息） |
| GET/POST | `/api/v1/ddns/credentials` | 凭据列表 / 新增凭据 |
| PUT/DELETE | `/api/v1/ddns/credentials/:id` | 修改（合并式更新）/ 删除凭据（被引用时拒绝） |
| POST | `/api/v1/ddns/credentials/:id/test` | 连通测试：用该凭据查询记录当前值 |
| GET/POST | `/api/v1/ddns/machines` | 机器列表 / 新增 |
| PUT/DELETE | `/api/v1/ddns/machines/:id` | 修改 / 删除机器 |
| POST | `/api/v1/ddns/groups` | 新增分组（`mode` 支持 rotate / interval / window / static） |
| PUT/DELETE | `/api/v1/ddns/groups/:id` | 修改 / 删除分组 |
| PUT | `/api/v1/ddns/groups/:id/members` | 全量保存组内成员与排班参数（`days` / `window_*` / `sort_order`） |
| GET/POST | `/api/v1/ddns/records` | 记录列表（走 overview）/ 新增（`credentialId` 引用凭据） |
| PUT/DELETE | `/api/v1/ddns/records/:id` | 修改（含改绑 `credentialId`）/ 删除 |
| POST | `/api/v1/ddns/sync` | 手动同步（body: `{force:true, groupId?}`） |
| GET | `/api/v1/ddns/preview?group_id=&days=` | 预览未来排班 |

> 全部接口均需管理员会话（`scope: admin`）。凭据明文与密文都不返回前端，只回脱敏值。

### 数据迁移

旧版本把凭据内嵌在每条解析记录里（`ddns_records.credential_enc`）。升级后首次请求会
**自动把内嵌凭据提升为独立凭据记录并回填 `credential_id`**（幂等，直接搬移密文），历史数据不丢。
